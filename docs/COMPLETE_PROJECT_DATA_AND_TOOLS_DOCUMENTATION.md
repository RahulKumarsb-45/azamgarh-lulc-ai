## 1. Executive Summary & Provenance Manifesto

This master documentation provides an exhaustive, forensic, and scientifically verifiable record of every software tool, library, dataset, image, algorithm, and mathematical model utilized in the **Azamgarh LULC Project**.

### Core Scientific & Data Truths:
1. **The Currently Displayed Maps and Visuals are Synthetic Demonstration Fixtures:**
   All 2019, 2022, and 2025 historical land-cover rasters, 2030 and 2035 future projections, and validation metrics currently visible in the Streamlit web dashboard originate from mathematically simulated $100 \times 100$ NumPy test fixtures generated by `src/data/synthetic_fixture.py`. They are **not** Copernicus Sentinel-2 satellite photographs or raw spectral band measurements.
2. **Zero Satellite Imagery Has Been Secretly Ingested:**
   The workspace input directories (`data/raw/`, `data/labels/`, and `data/processed/`) contain only `.gitkeep` placeholder files. No user-supplied optical rasters or field boundary shapefiles were used.
3. **Decoupled Architecture Explains Operation Without an API Key:**
   The Streamlit dashboard does not send HTTP requests to Google Earth Engine or ESA Copernicus Hub at runtime. It loads pre-computed local files (`.npy`, `.csv`, `.json`) from `data/outputs/` and renders them in the browser using client-side SVG/Canvas libraries (Plotly Express and Matplotlib).
4. **Authentic Satellite Pipeline is Fully Implemented:**
   The codebase includes complete, operational modules for live Google Earth Engine data ingestion (`src/data/gee_init.py` and `src/data/data_audit.py`). Activating live Earth Engine queries requires configuring `.env` with an active Google Cloud Project ID and executing `earthengine authenticate`.

### Technical Definitions for Viva Voce & Technical Defense:
- **API Key:** A static alphanumeric token passed in headers/URLs identifying the calling application (often used for read-only quota tracking). *Earth Engine does not use simple static API keys for Python data queries.*
- **GCP Project ID (`EE_PROJECT`):** The unique identifier of your Google Cloud Project (e.g., `azamgarh-lulc-2026`) that hosts enabled cloud services and tracks computational quotas.
- **User OAuth2 Credentials:** A locally cached security token generated when you log into Google via your web browser (`earthengine authenticate`). Stored strictly in your operating system user home directory (`~/.config/earthengine/credentials`), **never inside the project git folder**.
- **Service Account Key:** A private JSON key file granting automated server-to-server access without browser prompts. Not utilized in this student research setup.

## 7. Historical Change Detection Methodology

### 1. Temporal Analysis Windows
The project investigates landscape transformations across three benchmark years:
- **$T_1 = 2019$:** Pre-pandemic agricultural and rural settlement baseline.
- **$T_2 = 2022$:** Intermediate checkpoint (used for CA-Markov calibration and backtesting).
- **$T_3 = 2025$:** Contemporary baseline reflecting recent infrastructure and urban growth.

### 2. Standardized 5-Class Categorical Schema
Defined in `config/class_schema.yaml`:
- **Class 1 (Cropland / Agriculture):** Rotational double-cropped Gangetic alluvium (wheat, rice, mustard); high seasonal NDVI swing.
- **Class 2 (Vegetation):** Orchards, groves, canal-side plantations, dense tree canopies; sustained perennial greenness.
- **Class 3 (Water Bodies):** Tamsa River channel, oxbow wetlands, reservoirs, and village irrigation ponds.
- **Class 4 (Built-up Areas):** Azamgarh municipal center, tehsil towns, industrial surfaces, and rural homesteads.
- **Class 5 (Barren / Open Land):** Perennially bare soil, open fallow, and riverbed sand deposits.

### 3. Spatial Resolution & Metric Area Conversion
- **Raster Dimensions:** $100 \times 100$ cells ($10,000$ total pixels).
- **Official Study Area Benchmark:** $4,054.0\text{ km}^2$ ($405,400\text{ ha}$) based on official District Census records.
- **Pixel Area Equivalent:** $\frac{4,054.0\text{ km}^2}{10,000\text{ pixels}} = 0.4054\text{ km}^2/\text{pixel}$ ($40.54\text{ ha/pixel}$).
- **Conservation Law:** $\sum_{k=1}^5 \text{Area}_k = 4,054.00\text{ km}^2 \equiv 100.00\%$ across every time period.

### 4. Transition Matrix & Cross-Tabulation
Implemented in `src/analysis/change_detection.py:detect_land_cover_changes()`:
- Evaluates categorical shift matrix $C_{ij}$ tracking pixels where class at $T_1$ equals $i$ and class at $T_2$ equals $j$.
- Identifies critical socio-ecological transitions:
  * **Cropland $\to$ Built-up Conversion:** $414\text{ pixels}$ converted ($167.84\text{ km}^2$ / $16,784\text{ ha}$, representing $4.14\%$ of the district landscape in the synthetic test grid).
  * **Vegetation Loss / Conversion:** $178\text{ pixels}$ converted ($72.16\text{ km}^2$ / $7,216\text{ ha}$).

### 5. Spatial Change Hotspot Convolution
Implemented in `src/analysis/change_detection.py:identify_change_hotspots()`:
- Converts transition map into binary change matrix: $M_{xy} = 1$ if $LULC_{2019}(x, y) \ne LULC_{2025}(x, y)$, else $0$.
- Convolves $M$ with a $15 \times 15$ pixel spatial kernel ($\approx 1.2\text{ km} \times 1.2\text{ km}$ spatial moving window).
- Computes local change intensity (\%) to identify concentrated clusters of urban encroachment along highway corridors.

## 8. Future LULC Prediction (CA-Markov) & Backtesting

### 1. Why CA-Markov Modeling?
Standard Markov chains predict the **quantity** of future change (how many hectares will convert) based on transition probabilities, but have **zero spatial knowledge** (they cannot predict **where** changes will occur).  
**Cellular Automata (CA)** provides the spatial mechanism: land conversion does not occur uniformly at random; it aggregates adjacent to existing infrastructure, roads, and settlements.

### 2. Mathematical Formulation
1. **Transition Probability Matrix ($P$):**
   Calculated from observed historical cross-tabulation ($N_{ij}$ from $T_1$ to $T_2$):
   $$P_{ij} = \frac{N_{ij}}{\sum_{k=1}^m N_{ik}}$$
   Strictly normalized to row-stochastic form: $\sum_{j=1}^m P_{ij} = 1.0$.

2. **Area Projection:**
   $$v_{t+n} = v_t \times P^n$$
   Where $v_t$ is the class area distribution vector at time $t$, and $n$ is the forecast step.

3. **Cellular Automata Spatial Contiguity Allocation:**
   Implemented in `src/models/prediction.py:cellular_automata_markov_simulation()`:
   - For each pixel $(x, y)$, local neighborhood suitability $S_j(x, y)$ for class $j$ is computed using a $5 \times 5$ Moore neighborhood spatial convolution:
     $$S_j(x, y) = \sum_{u, v \in \mathcal{N}} K(u, v) \cdot I\left(\text{map}(x+u, y+v) == j\right)$$
   - The effective transition probability from class $i$ to class $j$ is scaled by neighborhood density:
     $$P_{\text{eff}}(i \to j) = P_{ij} \times \left(1.0 + 2.0 \cdot S_j(x, y)\right)$$
   - Pixels undergo stochastic transition based on Monte Carlo draws against $P_{\text{eff}} / \text{iterations}$.

### 3. Mandatory Historical Backtesting Protocol
To avoid making blind future projections, the forecasting baseline was rigorously evaluated by **hindcasting 2025**:
1. **Calibration:** The model was calibrated strictly on $2019 \to 2022$ transitions (withholding the actual 2025 map).
2. **Blind Simulation:** CA-Markov simulated the landscape forward to 2025.
3. **Validation Against Observed 2025:** Evaluated pixel-by-pixel against the classified 2025 map.
   - **Overall Spatial Agreement:** **95.72%** (Driven primarily by background landscape stability).
   - **Cohen's Kappa ($\kappa$):** **0.909** (Substantial agreement above chance).
   - **Figure of Merit (FoM):** **0.0161 (1.61%)** (Pontius et al. 2008 metric measuring spatial accuracy strictly over dynamic change pixels).

### 4. Assumptions and Limitations
- **Stationarity Assumption:** Assumes transition rates and urban drivers observed between 2019 and 2025 remain constant into 2030 and 2035.
- **Exogenous Policy Shocks:** Major new expressways (e.g. Purvanchal Expressway spur developments), government industrial corridors, or climate shocks are not modeled.
- **Demonstration Baseline:** Because current inputs are synthetic grids, projected hectares (e.g. Built-up expanding to $512.4\text{ km}^2$ by 2035) represent algorithmic demonstrations, not empirical forecasts for Azamgarh.

## 10. Live Satellite Mode vs. Demonstration Mode

### Why the System Currently Displays Demonstration Data:
When downloading or opening the repository offline, the user has not yet configured their personal Google Cloud credentials. If the software attempted to call Google Earth Engine without credentials, the entire program would crash with authentication errors.  
To ensure the software is **100% testable, demonstrable, and interactive**, the architecture includes a comprehensive **offline verification fallback**:
1. The pipeline runs locally using mathematically verified test fixtures (`data/synthetic_fixture/`).
2. All algorithms—Random Forest, Spatial Block Cross-Validation, Olofsson Error Adjustments, Matrix Multiplication, and Cellular Automata—execute on real CPU threads.
3. Provenance metadata (`data/outputs/provenance.json`) explicitly flags `"is_synthetic": true`.
4. The dashboard detects this flag via `dashboard.data_loader.is_demo_mode()` and displays amber warning banners on every page to prevent synthetic figures from being mistaken for real-world measurements.

### Requirements to Transition from Demo Mode to Live Sentinel-2 Data:
To generate genuine Copernicus Sentinel-2 classified maps for Azamgarh:
1. Create a Google Cloud Project and enable the Earth Engine API at [console.cloud.google.com](https://console.cloud.google.com/).
2. Copy `.env.example` to `.env` and set your Project ID:
   ```powershell
   Copy-Item .env.example .env
   # Inside .env: EE_PROJECT=your-actual-gcp-project-id
   ```
3. Authenticate your Google user profile:
   ```powershell
   earthengine authenticate
   ```
4. Execute the live satellite audit and master pipeline:
   ```powershell
   python src/data/data_audit.py
   python src/pipeline.py --mode live
   ```
5. When complete, `data/outputs/provenance.json` will update to `"is_synthetic": false`, and the dashboard will automatically display genuine Sentinel-2 classification rasters.
